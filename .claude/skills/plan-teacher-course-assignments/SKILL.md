# 教師配課規劃

把配課視為受限制的配置問題與雙重會計問題：同時維護「班級實際週節數」及「每位教師個人負擔」，不可用其中一套代替另一套。

## 讀取資料

1. 先列出所有可用檔案及版本日期。
2. 依序讀取上一學年度總配課表、當年度教師職務表、減課資料、已由領域自行規劃的資料、各領域確認版及目前總表。
3. 對 DOC/DOCX、試算表或 PDF，同時使用相應的文件技能；修改 DOCX 時必須保留原格式並完成逐頁渲染檢查。
4. 建立來源權威表，記錄檔名、日期、涵蓋範圍、狀態與衝突。採用以下優先順序：
   - 使用者最新明確決定。
   - 當年度正式資料在各自範圍內的內容，例如職務表決定人員與職務，減課表決定減課，領域確認版決定已定稿課程。
   - 目前工作版或暫定版。
   - 上一學年度資料只用於推定教學領域與配置邏輯，不得直接帶入離職教師或舊缺額。
5. 將每項資訊標為 `confirmed`、`proposed`、`open` 或 `conflict`，禁止把推測寫成已確認。

開始新年度規劃前，完整閱讀 [planning-ledgers.md](references/planning-ledgers.md)。需要檢核資料格式時，再讀 [ledger-schema.md](references/ledger-schema.md)。

## 建立四本帳

維護以下四本帳，並在每次使用者修改後同步更新：

- 人員帳：姓名、當年度是否在職、職務、導師或科任身分、專長、基本節數、各項減課、有效目標、可否超鐘點、時間或年段限制、固定課程。
- 班級帳：班級、年級、班型、每週總節數、課程結構、特殊班排除項目及共同授課規則。
- 配課帳：班級、課程槽位、實際教學內容、教師、節數、共同授課、替代或新增、確認狀態、來源。
- 決策帳：使用者每次確認、撤回、改配與仍待決定事項，保留最新有效決定並標記被取代的舊決定。

## 鎖定硬限制

在提出配置前先確認：

- 當年度班級數、普通班與特殊班型、各年級週節數。
- 導師、科任、行政組長、主任等身分的基本節數。
- 減課如何影響目標節數，以及是否允許再超回去。
- 已離開當年度職務表的人員、新增行政人員及不參與配課人員。
- 已定稿的領域、固定班級、外師協同、代理與代課缺額。
- 年段跨度、下午可排課量、不可教授領域等個人限制。

遵守下列計數規則：

- `有效目標 = 基本節數 - 減課`；若政策允許超鐘點，超出有效目標不是錯誤，但要明列差額。
- 班級週節數中每個實際時段只計一次。共同授課可同時計入多位教師的個人負擔，但班級只計一節。
- 「取代既有課程」不得再增加班級週節數；配課帳以被占用的課程槽位記錄，另以教學內容說明實際課程。
- 普通班、體育班、管樂班或其他特殊班型分開計算。若特殊班不含閱讀、視覺、健康或其他普通班課程，不得套用全年級總班數。
- 代理、代課、兼課與待聘要分開命名並列出節數，不得以模糊的「缺老師」合併處理。
- 上年度教師僅能作為專長歷史證據；不在當年度人員範圍者不得配課。

## 逐領域規劃

1. 先配置限制最高的項目：特殊班專業課、固定行政授課、已由領域定稿的課、不可移動的班級與時段限制。
2. 再依相依性逐領域處理。通常先處理健康、本土語、自然、資訊、社會、閱讀、體育與英語；音樂與視覺若共享教師，放在一起或較後處理。
3. 每次只提出一個可驗證的小批次，列出：教師、班級、節數、個人新總量、未補缺額、受影響的其他領域。
4. 使用者確認後，立即更新四本帳並產出該領域確認版；未確認前不得寫成確定版。
5. 若調動一位教師，沿著所有相依項目重新檢查，例如總節數、協同課、另一領域負擔、代理缺額與特殊班排除。

## 進行「grill me」討論

當資料不完整、存在多種合理方案或使用者要求討論時，完整閱讀 [grill-me-playbook.md](references/grill-me-playbook.md)。每次聚焦一個決策，先說明已知、缺口、影響與建議，再問精確問題。不要詢問可從檔案直接查出的內容，也不要一次丟出整份未驗證方案。

## 執行檢核

每個領域定稿時執行局部檢核；合併總表前執行全域檢核：

1. 人員範圍：無離職或不參與配課者；姓名、職務與待聘名稱一致。
2. 課程覆蓋：每班每個課程槽位完整，沒有漏配、重複或把替代課誤算為新增課。
3. 班級閉合：每班獨立加總等於該班型週節數。
4. 教師負擔：逐人重算實際節數、基本節數、減課、有效目標、超鐘點或不足。
5. 共同授課：班級帳只計一次，個人帳依實際參與教師分別計入。
6. 缺額：代理、代課、兼課及待聘節數與班級明細相符。
7. 限制：年段跨度、專長、班型排除、可排課量與固定班級全部符合。
8. 版本一致：各領域確認版、總表前半部及後半部課程結構使用同一組最新決定。

為最終版建立 `schedule-ledger.json`，依 [ledger-schema.md](references/ledger-schema.md) 填寫。從本 `SKILL.md` 所在目錄解析檢核器的絕對路徑，不要假設工作區另有 `scripts/`，再執行：

```powershell
python "<skill-directory>/scripts/audit_schedule.py" schedule-ledger.json
```

解決所有 `ERROR`；每個 `WARN` 都要修正或在交付說明中解釋。工具通過後仍須逐班、逐師單筆檢核，不得只靠總數。

## 匯出成果

- 先保留各領域確認版，再合併完整總表。
- 沿用使用者指定的母版、欄位、色彩、註記與後半部課程結構，不得只重做前半部表格。
- 在後半部清楚區分班級週節數、導師主責、共同授課與教師個人負擔。
- 以日期與版本命名，保留上一版，避免覆蓋使用者已確認的檔案。
- 修改 DOCX 後逐頁渲染，確認無截字、重疊、異常換頁、表格位移或遺失段落，再交付。

若工作檔案屬於嘉北國小或沿用本次114至115學年度的邏輯，先閱讀 [jia-bei-lessons.md](references/jia-bei-lessons.md)，但仍以當年度正式資料與使用者最新決定為準。
